# AGENTS.md

Guidance for AI coding agents (Claude Code, etc.) working in this repository.

## Repository layout

```
mobile/          React Native app ($APP_FRAMEWORK from devcontainer.json: "expo" or "bare" React Native CLI;
                 package manager = $PKG_MANAGER)
.devcontainer/   Dev container: Node.js, JDK 17, Android SDK/NDK, Gradle caches, EAS CLI
Makefile         Entry point for all common tasks
```

Every Android toolchain (Node.js, JDK, Android SDK, NDK, CMake, Gradle) is available in this single container, so you can install, lint, type-check, test and build the Android app from the same shell. iOS cannot be built here (it needs macOS + Xcode): use `make eas-build-ios` (EAS cloud build) instead.

## Commands

| Task                                | Command                                         |
| ----------------------------------- | ----------------------------------------------- |
| Dev server (Metro / Expo)           | `make start` (port 8081, long-running)          |
| Build + run on device/emulator      | `make android`                                  |
| Connected devices                   | `make devices`                                  |
| Lint                                | `make lint`                                     |
| Type-check                          | `make typecheck`                                |
| Tests                               | `make test`                                     |
| Project health (versions, config)   | `make doctor`                                   |
| Generate `android/` (Expo only)     | `make prebuild`                                 |
| Local Android builds                | `make apk-debug` / `make apk` / `make aab`      |
| Cloud builds (EAS)                  | `make eas-build-android` / `make eas-build-ios` |

## Conventions

- All code comments in English.
- App code lives entirely under `mobile/`; never place JS/TS files at the repository root.
- Lint and type-check before finishing any task: `make lint && make typecheck`.
- Expo projects (`APP_FRAMEWORK=expo`):
  - `android/` and `ios/` are generated by `npx expo prebuild` (Continuous Native Generation) and ignored by Git. Change native configuration through `app.json` / config plugins, never by editing `android/` directly — it is overwritten on the next prebuild.
  - Add libraries with `npx expo install <package>` (inside `mobile/`) so the version matches the Expo SDK; use the package manager only for packages unrelated to React Native.
  - Configuration reaches the app only through `EXPO_PUBLIC_*` variables, which are inlined into the bundle: never put secrets in them.
- Bare projects (`APP_FRAMEWORK=bare`): `android/` is source code and is versioned; keep Gradle changes minimal and explain them.
- `make start` and `make android` start a long-running dev server. Do not start them just to verify a change; prefer `make lint`, `make typecheck`, `make test` and, for native changes, `make apk-debug`.

## Devices

- There is no Android emulator in the container. Devices are reached through ADB using `ADB_SERVER_SOCKET`:
  - `tcp:host.docker.internal:5037`: the ADB server runs on the host (host emulator or USB device).
  - `tcp:localhost:5037`: the container runs its own ADB server (Wi-Fi debugging, or USB passthrough).
- If `make devices` lists nothing, tell the user instead of trying to create or start an emulator.

## Caches (do not delete)

- `/opt/android-sdk` is a persistent volume (Android SDK, NDK, CMake). Install extra packages with `sdkmanager`.
- `~/.gradle` is a persistent volume (Gradle distributions and dependency cache).
- `mobile/node_modules` is a persistent volume; do not remove it wholesale, use the package manager.
- `~/.android` (ADB keys), `~/.expo` (Expo/EAS login), `~/.npm` and the pnpm store are persistent volumes.
- `~/.claude` is a persistent volume (Claude Code credentials and settings).
